# التحقق على الجهاز — بوردي

استخدم هذا الإجراء بعد كل تغيير في الواجهة أو السلوك أو مخطط قاعدة البيانات.

## الخطوات

1. `./scripts/build-debug.sh`
2. `./scripts/install-device.sh`
3. `./scripts/verify-ui.sh` (أو `./scripts/verify-ui.sh "حفظ"` لتصفية عقدة).
   **المصدر الوحيد للنصوص والإحداثيات هو `uiautomator dump`** — لا الصور.
4. نفّذ التدفق المتأثر + حالة حدية واحدة على الأقل: قائمة فارغة، صفر، نقص مخزون، رفض صلاحية، انتهاء ترخيص.
5. لفحص البيانات: `./scripts/pull-db.sh` ثم افتح `bordy.db` و`bordy.db-wal` **معاً**.
6. أعد أي بيانات/مخزون أنشأته أو عدّلته، وأبلغ بما لم تستطع التحقق منه.

## مزالق مؤكدة على هذا الجهاز

- `adb shell input text` بالعربية يرمي NPE على الخادم → اكتب قيماً لاتينية للاختبار.
- في `OutlinedTextField` النقر يضع المؤشر عند 0 → امسح بـ forward-delete (`keyevent 112`) أو خليط 67/112.
- الكيبورد المفتوح يشوّه حوارات Compose ويحجب أزرارها → `keyevent 111` قبل أي dump تعتمد على إحداثياته.
- `uiautomator dump` لا يلتقط ورقة بصمة سامسونج — أثبت حدوثها بتسجيل من داخل التطبيق لا من الشجرة.
- `logcat -d -t 400` يغطي أقل من ثانية → `logcat -c` قبل الحدث ثم `logcat -d -s TAG`.
- كل أمر adb فيه مسار مثل `/sdcard/...` يجب أن يعمل مع `MSYS_NO_PATHCONV=1` وإلا حُوِّل المسار وأخفى الفشل.
- لا تسحب `db` والتطبيق يعمل (زوج غير متسق → malformed)؛ السكربت يوقف التطبيق أولاً ثم أعد تشغيله.
- تجميع ضغطات المفاتيح في أمر واحد (`input keyevent 67 67 67`) — أوامر adb المتكررة استنزفت ذاكرة Windows سابقاً.
- بعد `input swipe` انتظر ~3 ثوانٍ قبل الـ dump (قصور القائمة).
- لا تحذف صفاً لم تنشئه في هذه الجلسة؛ راجع `createdAt` — قد يكون عمل المستخدم الحقيقي.
